# 采集完整性与消息归属核对

本页仅记录通用工程检查方法，不包含实际账号、群、消息、帖子或本地数据库统计。

- 退群、好友列表变化和当前接口不可见都不能证明历史记录不存在。
- 短页本身不能证明历史采集结束；需要空页、明确结束标记或已解释的重复边界，并保留原始响应。
- 每个账号、会话与历史方向维护独立游标；采集任务结束不等于数据范围完整。
- 对照历史 HTTP 与实时 WS 来源分别统计原始响应、标准化成功数、解析失败数和时间范围。
- 私聊发送者与会话对端是两个字段；历史请求的对端信息必须保留，不能根据发送者直接推断收件人。
- 消息与媒体的版本变化应追溯原始记录，不应把当前归一化状态当作曾经全部可见数据。
- 对 `not_attempted`、`partial`、`source_empty`、`complete` 等状态保留可核对的依据；出错和未知状态不能改写为成功。

真实业务排查报告应保存在仓库之外；用于单元测试与发布文档的例子使用合成标识符和内容。
