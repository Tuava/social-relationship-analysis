# 人员关系档案字段表

## 目的

这份文档定义"点击一个人之后，右侧必须能回答哪些问题"。
它是采集端和展示端的共同合同：采集端按此表确定采什么，展示端按此表确定展示什么。

每一条字段都包含：
- **问题**：用户要得到的答案
- **数据**：回答该问题需要的具体数据
- **来源**：数据从哪个接口获得
- **完整度判定**：如何区分"确实没有"与"还没采到"
- **展示位置**：在右侧面板的哪个区域

## 一、身份区（顶部）

### 1.1 当前头像

| 项目 | 内容 |
|------|------|
| 问题 | 这个人长什么样 |
| 数据 | 最近一张已下载的头像图片 |
| 来源 | person_profiles.avatar_uri 或 media_references(media_kind='avatar', status='completed') |
| 完整度 | completed=已完成；pending/failed=采集中或失败；无记录=未采集 |
| 展示 | 顶部圆形头像 |

### 1.2 历史头像

| 项目 | 内容 |
|------|------|
| 问题 | 这个人用过哪些头像 |
| 数据 | 按时间排列的头像列表，每张带发现时间和来源 |
| 来源 | 每次 get_group_member_info / get_user_info / get_stranger_info 返回的 avatar 字段，去重后入 media_references |
| 完整度 | 已下载 N 张 / 已发现 M 张 |
| 展示 | 资料区头像时间线 |

### 1.3 当前昵称

| 项目 | 内容 |
|------|------|
| 问题 | 这个人现在叫什么 |
| 数据 | persons.display_name（取最新 profile 的 nickname） |
| 来源 | 任意接口返回的 nickname 字段 |
| 完整度 | 有值=已有；空=未采集 |
| 展示 | 顶部主标题 |

### 1.4 历史昵称

| 项目 | 内容 |
|------|------|
| 问题 | 这个人用过哪些名字 |
| 数据 | person_profiles.nickname 按时间排列，带 valid_from / valid_to |
| 来源 | get_group_member_info / get_user_info / get_stranger_info / get_friend_list |
| 完整度 | 已记录 N 次变化 |
| 展示 | 资料区昵称时间线 |

### 1.5 QQ 号

| 项目 | 内容 |
|------|------|
| 问题 | 这个人的唯一标识是什么 |
| 数据 | person_identifiers(platform='qq').platform_user_id |
| 来源 | 任意接口返回的 user_id / user_uin / qq 字段 |
| 完整度 | 必有 |
| 展示 | 顶部副标题 |

### 1.6 个性签名

| 项目 | 内容 |
|------|------|
| 问题 | 这个人怎么描述自己 |
| 数据 | person_profiles.profile_data.signature（按时间保留变化） |
| 来源 | get_user_info / get_stranger_info |
| 完整度 | 有值=已有；空且已调用接口=确实没有；未调用=未采集 |
| 展示 | 资料区 |

### 1.7 性别 / 年龄 / 地区

| 项目 | 内容 |
|------|------|
| 问题 | 基本人口特征 |
| 数据 | person_profiles.profile_data 中的 sex / age / area / country / province / city |
| 来源 | get_user_info / get_stranger_info |
| 完整度 | 同 1.6 |
| 展示 | 资料区 |

### 1.8 学校 / 职业 / 公司

| 项目 | 内容 |
|------|------|
| 问题 | 社会身份线索 |
| 数据 | person_profiles.profile_data 中的 school / company / profession / reg_time / login_days |
| 来源 | get_user_info（需确认 NapCat 是否返回这些字段，可能需要 QZone 接口补充） |
| 完整度 | 同 1.6；额外标记"接口不支持"状态 |
| 展示 | 资料区 |

### 1.9 好友备注

| 项目 | 内容 |
|------|------|
| 问题 | 目标账号给他标了什么注 |
| 数据 | person_profiles.card_or_remark（source='friend_list'） |
| 来源 | get_friend_list |
| 完整度 | 有值=已有；空且目标未加好友=不适用；未采集=未采集 |
| 展示 | 资料区 |

### 1.10 群名片（每个群独立）

| 项目 | 内容 |
|------|------|
| 问题 | 他在各个群里叫什么、什么角色 |
| 数据 | group_memberships（含 role、card），关联到具体群 |
| 来源 | get_group_member_list / get_group_member_info |
| 完整度 | 已采集 N 个群的成员信息 / 目标可见 M 个群 |
| 展示 | 资料区群名片表 |

### 1.11 与目标的关系定位

| 项目 | 内容 |
|------|------|
| 问题 | 他是目标的什么人 |
| 数据 | 关系类型标签：直接好友 / 同群成员 / 空间互动 / 间接发现 |
| 来源 | get_friend_list + group_memberships + relation_events 综合判定 |
| 完整度 | 至少有一种关系证据=已定位；否则=待分析 |
| 展示 | 顶部标签 |

## 二、关系区（核心）

### 2.1 发现路径

| 项目 | 内容 |
|------|------|
| 问题 | 这个人是怎么进入关系图的 |
| 数据 | 从目标到此人的一条或多条最短路径，每条路径列出经过的节点和边 |
| 来源 | ego_network_edges + relation_events 回溯 |
| 完整度 | 至少一条=已发现；零条=孤立节点 |
| 展示 | 关系区顶部，用文字描述 + 可展开路径详情 |

### 2.2 直接聊天

| 项目 | 内容 |
|------|------|
| 问题 | 他们私聊过多少、什么时候聊的 |
| 数据 | 私聊消息总数、时间范围、消息列表 |
| 来源 | get_friend_msg_history / get_private_msg_history（需确认 NapCat 接口名） |
| 完整度 | 已采集 N 条（首条时间 ~ 末条时间）/ 未采集 / 接口不可用 |
| 展示 | 关系区聊天摘要 + 可展开消息列表 |

### 2.3 共同群

| 项目 | 内容 |
|------|------|
| 问题 | 他们同时在哪些群里 |
| 数据 | 共同 group_id 列表，每群附带：群名、此人角色、此人消息数、目标消息数、共同活跃时间段 |
| 来源 | group_memberships 交集 + messages 按 conversation 统计 |
| 完整度 | 已确认 N 个共同群 / 已采集 M / 共 N 个群 |
| 展示 | 关系区共同群列表，可展开每群互动详情 |

### 2.4 群内互动

| 项目 | 内容 |
|------|------|
| 问题 | 他们在群里有没有直接对话、回复、@ |
| 数据 | 同群内此人与目标之间的 reply_to / mention 事件，按群分组 |
| 来源 | messages.message_segments 中的 reply / at 字段 + relation_events(action_type='replied_to'/'mentioned') |
| 完整度 | 已分析 N 个群的互动 / 共 M 个共同群 |
| 展示 | 关系区群内互动列表 |

### 2.5 空间动态互动

| 项目 | 内容 |
|------|------|
| 问题 | 他们在空间有没有点赞、评论、回复 |
| 数据 | 此人对目标动态的评论/点赞 + 目标对此人动态的评论/点赞 |
| 来源 | get_comment_list + get_like_list（针对目标和此人的动态） |
| 完整度 | 已扫描目标动态 N 条中 M 条有此人的互动 / 此人动态已采集 K 条 |
| 展示 | 关系区空间互动列表 |

### 2.6 空间访问

| 项目 | 内容 |
|------|------|
| 问题 | 他们有没有互访空间 |
| 数据 | 此人出现在目标访客列表 / 目标出现在此人访客列表 |
| 来源 | QZone get_visit_list |
| 完整度 | 已采集 / 未采集 / 接口受限 |
| 展示 | 关系区访客记录 |

### 2.7 共同联系人

| 项目 | 内容 |
|------|------|
| 问题 | 他们有没有共同好友或共同群友 |
| 数据 | 与两人都有直接关系的第三人列表 |
| 来源 | relation_events 三角查询 |
| 完整度 | 已发现 N 个共同联系人 |
| 展示 | 关系区共同联系人列表 |

### 2.8 互动时间分布

| 项目 | 内容 |
|------|------|
| 问题 | 他们的关系什么时候最密切 |
| 数据 | 按月/周/日统计的互动次数时间序列（消息+评论+点赞+访问） |
| 来源 | relation_events 按时间聚合 |
| 完整度 | 至少有一个时间点的数据=已有 |
| 展示 | 关系区时间分布图 |

### 2.9 关系趋势

| 项目 | 内容 |
|------|------|
| 问题 | 他们的关系在增强还是减弱 |
| 数据 | 近30天 vs 前30天互动量对比；近7天 vs 前7天 |
| 来源 | relation_events 时间窗口对比 |
| 完整度 | 有足够时间跨度数据=可计算；否则=数据不足 |
| 展示 | 关系区趋势标签（上升/平稳/下降/新建立） |

### 2.10 首次和最近互动

| 项目 | 内容 |
|------|------|
| 问题 | 他们什么时候第一次出现交集，最近一次是什么时候 |
| 数据 | relation_events 中涉及此人的最早和最晚 occurred_at |
| 来源 | relation_events |
| 完整度 | 有至少一条事件=已有 |
| 展示 | 关系区摘要行 |

## 三、时间线区

### 3.1 统一事件流

| 项目 | 内容 |
|------|------|
| 问题 | 这个人身上发生过哪些可观测的事，按时间排列 |
| 数据 | 所有事件按时间排序：发消息、入群、退群、发动态、评论、点赞、访问、改昵称、改头像、改签名 |
| 来源 | relation_events + messages + group_memberships + person_profiles + contents |
| 完整度 | 已有 N 条事件（首条时间 ~ 末条时间） |
| 展示 | 底部时间线，支持按事件类型和时间范围筛选 |

### 3.2 事件类型筛选

| 项目 | 内容 |
|------|------|
| 问题 | 只看某一类事件 |
| 数据 | 按事件类型过滤 |
| 来源 | 同 3.1 |
| 完整度 | 不适用 |
| 展示 | 时间线顶部筛选器 |

### 4.5 媒体资源

## 五、证据区

### 5.1 按关系结论组织

| 项目 | 内容 |
|------|------|
| 问题 | 上面每个关系结论的证据是什么 |
| 数据 | 每个结论对应的具体消息、动态、评论、群成员记录或原始接口响应 |
| 来源 | raw_records + relation_events.evidence_ids |
| 完整度 | 每条结论至少有一条证据=可验证 |
| 展示 | 按结论分组，每组可展开查看原始证据 |

### 5.2 证据结构

每条证据包含：
- 来源账号
- 采集时间
- 接口名称
- 原始 JSON 入口（点击可查看完整原始记录）
- 在结论中的作用说明

## 六、采集完整度区

### 6.1 覆盖表

| 数据项 | 来源接口 | 状态 | 详情 |
|--------|----------|------|------|
| 基础资料 | get_user_info | — | — |
| 历史头像 | 多接口 avatar 字段 | — | — |
| 好友关系 | get_friend_list | — | — |
| 共同群成员 | get_group_member_list | — | — |
| 群内消息 | get_group_msg_history | — | 每群已采条数 / 估计总量 |
| 私聊历史 | get_friend_msg_history | — | — |
| 空间动态 | QZone feeds | — | 已采条数 / 是否有下一页 |
| 动态评论 | get_comment_list | — | 已覆盖动态数 / 总动态数 |
| 动态点赞 | get_like_list | — | 已覆盖动态数 / 总动态数 |
| 空间访客 | QZone get_visit_list | — | — |
| 媒体资源 | media_references | — | 已归档 / 待下载 / 失败 |
| 实时消息 | WS | — | 连接状态 |

### 6.2 状态定义

| 状态 | 含义 |
|------|------|
| 未采集 | 尚未发起请求 |
| 采集中 | 任务正在运行 |
| 部分数据 | 分页未完成或接口受限 |
| 已完成 | 当前接口范围已扫完 |
| 无结果 | 已完成采集但没有发现 |
| 失效 | Cookie、权限或接口错误 |

### 6.3 深挖操作

| 项目 | 内容 |
|------|------|
| 问题 | 信息不足时怎么补充 |
| 数据 | 可发起的采集任务列表，每个带预览 |
| 来源 | 采集任务系统 |
| 完整度 | 不适用 |
| 展示 | 完整度区底部"继续深挖"按钮，点击后展开可选采集项 |

深挖可选项目：
1. 补充基础资料（get_user_info）
2. 采集空间动态（QZone feeds，按 user_id）
3. 采集动态评论（get_comment_list，针对此人动态）
4. 采集动态点赞（get_like_list，针对此人动态）
5. 采集私聊历史（get_friend_msg_history）
6. 下载头像和媒体（media_references）
7. 采集所在群的完整历史消息
