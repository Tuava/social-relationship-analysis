# 系统审计报告

> 审计时间：2026-08-14
> 审计依据：docs/person-profile-spec.md 人员关系档案字段表
> 审计方法：四个 agent 并行，分别审计身份区、关系区、内容/时间线/证据/完整度、接口缺口，交叉验证 DB/采集/API/前端 四层

---

## 一、全局结论

系统整体完成度按四层统计：

| 层 | 已有 | 部分 | 缺失 |
|----|------|------|------|
| 数据库 | 70% | 20% | 10% |
| 采集 | 30% | 25% | 45% |
| API | 25% | 20% | 55% |
| 前端 | 25% | 25% | 50% |

数据库层基础较好，但采集层只完成了不到三分之一，API 和前端层大面积缺失。系统处于"DB 先行、采集不全、读取展示未跟上"的半成品状态。

## 二、P0 缺口（必须先修，否则整个系统无意义）

### P0-1 群历史消息无分页 — 只取100条

- **位置**：collector.go:103，`GetGroupHistory(ctx, groupID, 100, 0)`
- **影响**：每个群只保留最新100条，历史互动几乎全丢。直接击穿关系图边密度、共同群活跃度、群内互动、时间线、消息展示
- **修复**：循环调用，用返回的 message_seq 向前翻页，直到没有更多消息

### P0-2 collection_cursors 断点续采完全未使用

- **位置**：migrations/001_init.sql 建了表，但 Go 代码零引用
- **影响**：任何分页采集中断后都从头重跑，大群永远采不完。是所有分页接口的公共地基
- **修复**：每次分页采集中写入 cursor，下次从 cursor 继续遍历

### P0-3 私聊历史完全未采集

- **位置**：全后端无 get_friend_msg_history 调用
- **影响**：目标与好友的1:1私聊互动边完全不存在。2.2 直接聊天从采集到前端四层全缺失
- **修复**：新增 GetFriendMsgHistory 客户端方法 + 分页循环 + 标准化

## 三、P1 缺口（核心功能严重残缺）

### P1-1 无"两人关系"专用 API

- **影响**：没有任何接口能回答"目标QQ与此人之间的互动"。person() 是单人维度，relationEvents 是无筛选的全局列表
- **修复**：新增 `GET /api/v1/persons/{id}/relationship?target_qq=...`，一次性返回共同群/直接聊天/空间互动/发现路径/时间分布/趋势/首末互动

### P1-2 群内 @/回复数据未结构化

- **位置**：message_segments 已存了 reply/at 原始 JSON，但归一化只写 sent_message
- **影响**：mentioned 全后端零产出，replied_to 仅来自 QZone 评论。2.4 群内互动无法查询
- **修复**：归一化阶段解析 reply/at，物化为 replied_to/mentioned 事件

### P1-3 点赞列表无分页

- **位置**：collector.go:120，单次取首页
- **影响**：每条动态的点赞者往往远超一页，绝大多数点赞边丢失。评论完整、点赞残缺导致空间互动权重失真
- **修复**：循环调用，pos/num 前进

### P1-4 统一时间线全链路断裂

- **影响**：DB 时间字段齐全、采集端事件丰富，但无 /timeline API，前端 viewMode="timeline" 是死代码
- **修复**：新增 `GET /api/v1/persons/{id}/timeline`，聚合所有事件按时间排序，支持类型筛选

### P1-5 点赞记录存了取不出

- **位置**：content handler 不返回点赞，relationEvents 不支持按 target_object_id 筛选
- **影响**：没有任何 API 能取回某条动态的点赞人列表，前端点赞 tab 永远显示回退文案
- **修复**：content handler 增加点赞列表，或 relationEvents 支持 target_object_id 筛选

### P1-6 前端关系区面板几乎不存在

- **影响**：EgoNetworksPage 右侧是图节点探查器，非 spec 定义的关系区。发现路径/直接聊天/共同群/群内互动/空间互动/访客/共同联系人/时间分布/趋势 — 9个子区无一展示

## 四、P2 缺口（身份与资料不完整）

### P2-1 群名片整链断裂

- **位置**：group_memberships 表无 card 列，采集把 card 错误塞进 person_profiles.card_or_remark
- **影响**：好友备注与群名片混存，无法区分。1.10 从 DB 到 UI 全链路缺失
- **修复**：加 card 列 → 采集改写 → API 返回 → 前端展示

### P2-2 get_stranger_info 字段未结构化

- **位置**：UpsertProfileData 把整个响应塞进 profile_data jsonb，未抽取 sex/age/area/school/company
- **影响**：1.6-1.8 字段无法按字段级查询和展示。school/company/profession 全代码库零出现

### P2-3 历史头像实质未保留

- **位置**：NapCat QueueAvatar 始终用固定 canonical URL，同一 QQ 永远只一行
- **影响**：头像变更历史丢失。API 不返回头像列表，前端无时间线

### P2-4 历史昵称时间区间不完整

- **位置**：valid_to 从不写入，每次 INSERT 新行无去重
- **影响**：同一昵称重复堆积，无法还原昵称变化时间线

### P2-5 回复上下文丢失

- **位置**：reply_to_message_id 列存在但 normalizer 从不写入
- **影响**：消息回复链断裂，无法还原对话上下文

### P2-6 评论嵌套未建模

- **位置**：评论间回复记为人→人 replied_to 事件，parent_content_id 只挂到帖子
- **影响**：所有评论平铺，无法还原评论树

## 五、P3 缺口（扩展能力缺失）

### P3-1 采集完整度体系不存在

- collection_cursors 零引用，collection_runs 只有3种粗粒度类型
- 无法区分"确实没有"与"还没采到"
- 无 /completeness API，无覆盖看板 UI
- 状态模型只有5态，缺"未采集""无结果""部分数据"

### P3-2 深挖操作不完整

- createCollectionRun 只接受3种类型，无 spec 列的7项粒度深挖
- 无从关系图直接发起某人补采的能力

### P3-3 群文件/相册/公告/荣誉/最近联系人全部未实现

- OpenAPI 中接口都存在，但 Go 客户端无方法、流程无调用

### P3-4 get_group_member_info 未实现

- 仅有批量 list，无单人详情。level/join_time/last_active/title 缺失

### P3-5 两人关系证据缺失

- 证据仅在 ego 网络边级别可查，PersonsPage 无证据区
- raw_records 无 conclusion 字段，无法按结论分组
